# #32 — Handle GraphQL codegen's dependency on a live Hasura endpoint for typecheck/build

## Summary
`apps/frontend`'s `typecheck` and `build` scripts fail without network access to a live `NEXT_PUBLIC_HASURA_GRAPHQL_URL`, because `src/graphql/generated/` (gitignored, produced by `yarn codegen`) doesn't exist until then. Every file importing from `@/graphql/generated` (e.g. `src/graphql/queries/apartment-queries.ts`) fails with `Cannot find module`.

## Impact
A fresh clone can't typecheck or produce a production build offline, and CI (once #36 exists) will need a reachable Hasura instance or a checked-in fallback schema just to pass typecheck.

## Options to evaluate
1. Commit a baseline `src/graphql/generated/` snapshot for offline typecheck, regenerated in CI against a real schema.
2. Stand up a lightweight mock/introspection schema for CI use.
3. Document this as an explicit prerequisite in `apps/frontend/README.md` (partially done) and make the build script's fallback behavior more visible in logs.

## Acceptance criteria
- [ ] `yarn workspace @truestub/frontend typecheck` succeeds without network access, or the requirement is clearly documented and enforced in CI.

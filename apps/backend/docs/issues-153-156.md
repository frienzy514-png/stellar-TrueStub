# Issues #153–#156: Implementation Notes

## #153 — Refund Idempotency Guard (`RefundAlreadyClaimed`)

**Route:** `POST /api/refunds/claim` · `GET /api/refunds/claim/:refundId`

### How it works
A refund claim is keyed by `refundId` (e.g. the on-chain transaction hash).
The first call stores the claim and returns `201`. Any subsequent call with
the same `refundId` returns `409 REFUND_ALREADY_CLAIMED` along with the
original claim record, so the caller can return an idempotent response.

### Storage cleanup
Claimed records accumulate in memory (default) or in the backing store.
Call `refundService.cleanup(retentionDays)` periodically to evict stale
records. Recommended schedule:

```
# cron — every day at 02:00 UTC, retain 90 days
0 2 * * *  node -e "require('./dist/services/refund.service').refundService.cleanup(90)"
```

For DB-backed stores, add a scheduled `DELETE WHERE claimed_at < now() - interval '90 days'`.

## #154 — Atomic Ownership Transfer Workflow

**Routes:**
- `POST /api/transfers/initiate` — start a transfer (PENDING)
- `POST /api/transfers/:id/accept` — PENDING → ACCEPTED
- `POST /api/transfers/:id/cancel` — PENDING → CANCELLED
- `GET  /api/transfers/:id` — read current state

### State machine
```
(start) → PENDING → ACCEPTED  (final)
                 → CANCELLED  (final)
```

### Atomicity
Each transfer state change holds a per-`transferId` in-process mutex.
Two concurrent `accept` calls for the same transfer will result in exactly
one success and one `409 TRANSFER_ALREADY_FINALIZED`. For multi-node
deployments, replace `InMemoryOwnershipStore` with a DB-backed store that
uses `SELECT FOR UPDATE` row locking.

## #155 — Changelog Entry Immutability (Write-Once)

**Routes:**
- `POST   /api/changelog`                      — append entry
- `GET    /api/changelog/:entryId`             — read entry
- `GET    /api/changelog/resource/:resourceId` — list entries for a resource
- `DELETE /api/changelog/:entryId`             — remove entry (audit event emitted)
- `PUT    /api/changelog/:entryId`             — **always 409 CHANGELOG_UPDATE_FORBIDDEN**
- `PATCH  /api/changelog/:entryId`             — **always 409 CHANGELOG_UPDATE_FORBIDDEN**

### Write-once contract
Entries cannot be updated after creation. To correct a wrong entry:

1. `DELETE /api/changelog/:entryId`
2. `POST   /api/changelog` with the corrected data

Every mutation emits an internal event (`ENTRY_APPENDED` / `ENTRY_REMOVED`)
for audit-log consumers. Register a listener via `changelogService.onEvent(fn)`.

## #156 — Dispute State Machine

**Routes:**
- `POST /api/disputes`                      — open dispute (OPEN state)
- `GET  /api/disputes/:id`                  — read dispute
- `GET  /api/disputes/escrow/:escrowId`     — list disputes for an escrow
- `POST /api/disputes/:id/escalate`         — OPEN → ESCALATED
- `POST /api/disputes/:id/resolve`          — OPEN|ESCALATED → RESOLVED
- `POST /api/disputes/:id/withdraw`         — OPEN|ESCALATED → WITHDRAWN

### State machine diagram

```
(open)
  │
  ▼
[OPEN] ──── escalate ───► [ESCALATED]
  │                            │
  │ resolve                    │ resolve
  │                            │
  ▼                            ▼
[RESOLVED] ◄───────────── [RESOLVED]   ← final

[OPEN]      ── withdraw ──► [WITHDRAWN]  ← final
[ESCALATED] ── withdraw ──► [WITHDRAWN]  ← final
```

### Valid transitions

| From       | Event    | To        |
|------------|----------|-----------|
| OPEN       | escalate | ESCALATED |
| OPEN       | resolve  | RESOLVED  |
| OPEN       | withdraw | WITHDRAWN |
| ESCALATED  | resolve  | RESOLVED  |
| ESCALATED  | withdraw | WITHDRAWN |

### Error codes

| Code                        | HTTP | Meaning                               |
|-----------------------------|------|---------------------------------------|
| DISPUTE_INVALID_TRANSITION  | 422  | Event not valid from current state    |
| DISPUTE_ALREADY_FINAL       | 409  | Dispute is in RESOLVED or WITHDRAWN   |
| DISPUTE_NOT_FOUND           | 404  | No dispute with that ID               |
| DISPUTE_ALREADY_EXISTS      | 409  | Duplicate `disputeId`                 |
